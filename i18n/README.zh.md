## 今天 — 2026-09-15

给智能体所在的机器装上仪表 —— 看清装了什么，让会话一直活着，撤销那次错误的写入。

| 精选 | 是什么 | 为何引起注意 |
|------|-----------|--------------|
| **DeepSeek-V4.1-Flash** | 读时只动 8B、写时只动 16B 的 552B MoE，MIT 许可 | 采用 Causal Encoder-Decoder 架构，预填充每 token 激活 8B，解码激活 16B；1M 上下文，支持图像和文本输入，在 API 上替换 V4 Flash 的当天就把权重放上 Hugging Face —— 真正值得看的是模型卡上的 KV 缓存：每 token 约 890 字节，大约是 V4 Flash 的四分之一。长时间运行的智能体循环，往往先卡在缓存内存上，而不是跑分上 |
| **Hydra** | 关掉窗口会话依然在的智能体终端 | 桌面应用只是本地 PTY 守护进程的一个客户端，关掉之后 shell 和智能体照样运行，还能在不开入站端口的情况下从浏览器连上；它会找到并接续已有的 Claude Code、Codex、Copilot CLI、OpenCode、Cursor Agent 会话 —— 持久存在的单位是智能体会话，而不是标签页。本地代码为 MIT，Remote 服务另行闭源 |
| **Geiger** | 看清机器上的每个智能体，以及它们能碰到什么 | 只读的 `npx geiger-scan` 会盘点 Claude Code 设置、MCP 宿主配置、IDE 与浏览器扩展、全局 npm 包，并打上 EXECUTES、HOLDS-SECRETS、BROAD-FILESYSTEM 等标签，还能对照基线检测变化 —— 它看的是配置而非运行时行为，所以告诉你的是波及范围而不是发生了什么，但就这一点，大多数开发机现在也答不上来 |
| **EterDB** | 不用整库恢复，只撤销那一个坏事务 | 基于 Postgres 18，保留只追加的历史：只回滚某个事务碰过的行，连同数据恢复被删除的表，追踪读取了脏数据的后续写入，还能按过去某个时刻查询 —— PITR 会把出错之后的正常写入一起丢掉，而这类错误越来越多来自手握连接字符串的智能体。Apache 2.0 |
