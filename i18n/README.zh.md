## 这是什么

每天上新的东西太多，跟不完。这就是我的过滤器 —— 每天 3~5 条，各用一行说明为何值得一点。

## 今天 — 2026-09-01

回到本地 —— 模型和驱动它们的智能体，都在收缩到你手头已有的硬件里。

| 精选 | 是什么 | 为何引起注意 |
|------|-----------|--------------|
| **Muse Glimmer** | Meta 面向常驻本地智能体打造的 30B 开放权重模型 | 由 Meta Superintelligence Labs 以 Apache 2.0 发布，瞄准的是跑在笔记本而非数据中心上的智能体任务：多步规划、连续工具调用、失败恢复。关键不在参数量而在靶子——多数开放权重都被调成在对话和推理榜单上好看，而这个盯的是生产环境里真正会崩的地方，也就是出错之后的第五次工具调用 |
| **Ante** | 以单个离线二进制发布的编码智能体 | 一个无运行时依赖的 Rust 二进制，驱动十余家提供商或本地 GGUF 模型，全程不向外发一个包，并提供 TUI、无头、服务端与网关四种模式——效率数字是厂商自测且无人复现，但打包这一层的论点本身就成立：能用 scp 丢到机器上的智能体，和需要装 Node、注册账号的东西根本不是同一类工具 |
| **hax** | 用 C 写的、不糟蹋你终端回滚的终端智能体 | 原生 C 二进制、依赖极少、瞬时启动，通过 llama-server 把本地模型当一等公民——真正的差别在于对终端的礼貌：它只重绘正在流式输出的那一行和输入区，而不是整个霸占备用屏幕，于是会话结束后回滚记录仍在。听着微不足道，却正是人们反复重写这类工具的原因 |
| **MIDI autocomplete** | 帮你把钢琴乐句接下去的 125M 端上模型 | 一个人训练了一个预测后续几小节的小模型，并让它在浏览器里本地运行——这很好地展示了智能体层之下"回到本地"意味着什么：125M 这个量级的延迟预算足够小，模型可以坐进乐器的反馈回路里，而不是待在一次请求的另一头。当作构建日志读，而不是产品 |
