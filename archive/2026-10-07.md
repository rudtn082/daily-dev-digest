# Daily Dev Digest — 2026-10-07

> Theme: Agent plumbing — sandboxes, identities, inboxes and shared skills.

## Picks

### bVisor — an embedded bash sandbox for agents, written in Zig
An SDK and runtime that runs agent-issued bash on the host without a VM or container, intercepting Linux syscalls in userspace via seccomp user notify, gVisor-style. It claims ~2 ms sandbox spin-up and ships as a TypeScript SDK on npm, Linux only. It showed up on Show HN this month; the project itself calls it an early proof of concept, so treat it as an idea to watch, not something to depend on.

### sx — a package manager for AI skills, MCP configs and commands
A Go CLI (Apache 2.0) from sleuth-io that acts like a private registry for the assets your coding agents use: skills, rules, MCP configs, slash commands, hooks. You `sx add` a skill and teammates `sx install` it across Claude Code, Cursor, Copilot and others. It's on the radar because skills are piling up in individual dotfiles and teams have no versioned way to share them.

### MachineAuth — OAuth-style identity for AI agents and services
Open-source auth server that issues short-lived access tokens to bots and agents instead of long-lived API keys, with a dashboard to create, rotate, revoke and monitor machine credentials and no external database required. It surfaced on Show HN this month, riding the same worry as the sandbox pick: agents now hold real credentials, and leaked static keys are the weak link.

### e2a — an authenticated email gateway for AI agents
Apache 2.0 gateway that gives each agent its own address, delivers inbound mail by webhook or WebSocket, sends via HTTP API, and runs SPF/DKIM checks plus HMAC-signed sender headers. Outbound messages can pause for human approval. It ships TS and Python SDKs, a CLI and an MCP server, and needs only PostgreSQL. It's a concrete answer to "how does an agent safely talk to people over email".
