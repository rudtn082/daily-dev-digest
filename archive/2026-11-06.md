# Daily Dev Digest — 2026-11-06

> Theme: Defaults that bite, defaults that get fixed — and cheap things getting cheaper.

## Picks

### Alpine OpenSSH password bypass — a 257-byte password logs you in
Alpine's advisory describes a password-authentication bypass in sshd builds without PAM: musl's `crypt()` returns `*` as an error for keys over 256 bytes, and `*` is also the stored value for passwordless accounts, so the comparison succeeds. It needs a `*` account, another local account with a `$5$`/`$6$` hash, and a 257–1024 byte password. It is on the radar because it hit the HN front page the same day it was published and the fix needs a daemon restart, not just an upgrade. Workaround: `PasswordAuthentication no`. No CVE assigned at time of the advisory.

### Go encoding/json/v2 — stable in Go 1.27
The Go team's Nov 4 post says `encoding/json/v2` and `encoding/json/jsontext` graduate from experiment (Go 1.25) to stable in Go 1.27. v2 errors on invalid UTF-8 and duplicate names, matches field names case-sensitively, and takes options as arguments. v1 is built on v2 and stays supported indefinitely. The team claims Unmarshal gains of up to 10x and Marshal roughly at parity; those are the Go team's own benchmarks.

### Pyramid-JiT (pjit-21k) — a 2B text-to-image model trained for about $21K
Linum's research release is a 2.18B-parameter text-to-image model under Apache 2.0, trained on 64 H100s for a stated cost of $21,038. It is on the radar as a data point for how cheap a usable open image model has become. The authors are upfront that it cannot reliably render text or posters and struggles with full-body figures and multi-person scenes. I did not run it.

### Rivet — agent orchestration with S3 as the only dependency
Apache-2.0 orchestrator (Launch HN, YC W23) whose core unit is the Rivet Actor: a long-lived process with in-memory state and a SQLite database backed by object storage. S3, GCS, Azure Blob or S3-compatible stores are the only required dependency, with idle actors hibernating. It is on the radar for dropping the usual Postgres/queue stack for agent state. Latency and cost figures on the page are the project's own claims; early launch, verify before depending on it.
