# Daily Dev Digest — 2026-09-15

> Theme: Instruments for the agent's machine — see what's installed, keep sessions alive, undo the bad write.

## Picks

### DeepSeek-V4.1-Flash — a 552B MoE that reads with 8B and writes with 16B, MIT-licensed
The smallest model in DeepSeek's new architecture family: a Causal Encoder-Decoder where a 20-layer causal encoder feeds a 20-layer decoder, so prefill activates 8B parameters per token and decode 16B. 1M context, image and text input, weights on Hugging Face under MIT the same day it replaced V4 Flash on the API. On the radar for the model card's KV-cache number — about 890 bytes per token, roughly a quarter of V4 Flash — because long agent loops run out of cache memory long before they run out of benchmark.

### Hydra — an agentic terminal whose sessions outlive the window
A Rust-rendered terminal where the desktop app is just a client of a local PTY daemon, so shells and agents keep running after you close it, with an optional browser client and no inbound port. It reads the local session metadata of Claude Code, Codex CLI, Copilot CLI, OpenCode, Cursor Agent, Kimi CLI and others to list and resume what's already there. Interesting because it treats the agent session, not the tab, as the durable object. The local code is MIT; the Hydra Remote service is separate and proprietary. macOS and Linux.

### Geiger — see every agent on your machine and what it can touch
A read-only, dependency-free Node CLI (`npx geiger-scan`) that inventories Claude Code settings, MCP host configs, IDE and browser extensions, and global npm packages, then tags each with `EXECUTES`, `HOLDS-SECRETS`, `BROAD-FILESYSTEM`, `BROAD-WEB` or `NETWORK`, with HTML/JSON output and drift detection against a baseline. It reads config, not runtime behavior, so it tells you blast radius, not what happened — which is still more than most dev machines can answer today.

### EterDB — undo one bad transaction without restoring the whole database
Built on Postgres 18, it keeps append-only history so you can reverse only the rows a specific transaction touched, recover dropped columns and tables with their values, follow read dependencies to find downstream writes the bad one tainted, and query data as of a past moment. Point-in-time recovery throws away every good write after the bad one; this doesn't. Timely now that more writes come from agents holding a connection string. Engine and `eter` CLI are Apache 2.0.
