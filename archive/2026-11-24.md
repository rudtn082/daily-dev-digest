# Daily Dev Digest — 2026-11-24

> Theme: Fence the agent, shield the host

## Picks

### Shirudo — Cisco and OpenAI's open-source project for shielding live Linux systems before a patch exists
Announced Nov 23 by Cisco and OpenAI. Per the release, AI agents find a vulnerability, write a protective eBPF "shield," and test that it blocks the attack without breaking service; shields are cryptographically signed and go live only when the evidence says they are safe. It is on the radar as a concrete attempt at agent-written, verified mitigations for the gap between disclosure and patch. The release cites only two demos (Java4shell and a PHP flaw) and states no limitations or license in the text we could read; check the repo before relying on it.

### External sandboxes for coding agents — Prime Radiant and Simon Willison's three prototypes
On Nov 17, Simon Willison and Prime Radiant published an "external sandbox" pattern: the coding agent stays outside, and only the code it executes runs inside an isolated Linux environment limited to the folders and network hosts you allow. Three experimental implementations share a localhost API. It matters because it separates the agent from the thing that runs its commands. Coverage notes that not every tool call crosses the boundary (Claude Code's native Read and Edit tools stay on the host), and the authors call the prototypes unaudited for sensitive work.

### Infrastructure Agent Skills — Itential's open skills library for network and infrastructure agents
Itential released an Apache 2.0 library of reusable operational procedures and vendor-specific guidance for AI agents working on network and infrastructure tasks. Each skill covers platform-specific steps, error handling and verification, and follows the Agent Skills open standard. It is on the radar because it moves skills from generic coding help into ops work, where "verify before you change" is the whole point. Third-party skills stay in their publishers' repositories under their own licenses.
