# Daily Dev Digest — 2026-08-10

> Theme: The week agents stopped borrowing infrastructure and got their own — a machine, durable state, a memory of the loop — while the systems layer underneath got rewritten by the same models.

## Picks

### pgrust — Postgres reimplemented in Rust, line by line, mostly by a model
It is wire- and dialect-compatible with Postgres 18.3 and passes all 46,066 tests in the Postgres regression suite, which is the only number in this space that actually means something. The author's write-ups are the real artifact: four attempts, three dead ends, roughly $100k of model spend before a repeatable file-by-file translation process worked. Treat the benchmark claims (30% faster on OLTP, ahead of Clickhouse on Clickbench) as the author's own numbers, unreplicated. But "AI rewrote a database and it passes the suite" is a different category of claim from the usual demo, and it will be cited for the rest of the year either way.

### celld — self-hosted, distributed Durable Objects
Announced August 5 by Deno Land under Apache 2.0: a daemon that runs Wrangler bundles on your own machines by embedding V8, with each object as its own SQLite database, addressed by name and replicated to an S3-compatible bucket you control. The design choice worth stealing is coordination — nodes talk only through the bucket, with no control plane and no consensus layer to operate. Sharding stops being a migration you plan and becomes a property of the model. It is v0.1.0, so this is an architecture to read, not a thing to put under production traffic this week.

### @cloudflare/computer — give the agent a machine, not a container
Preview-released August 3 under MIT, ahead of Cloudflare's Agents Week. It is a Durable Object workspace with one filesystem behind multiple execution backends: fast isolates for file manipulation and data shuffling, full Linux containers mounted through FUSE when the task needs native binaries or a package manager. The interesting bet is that "one container per agent" was the wrong primitive — most agent steps are too small to justify a VM and a few need a whole userland, so the runtime routes per task rather than making you pick up front. Every operation is gated and audited, which is the part enterprises will actually read.

### LoopX — a state kernel for agent work that outlives the session
Provider-neutral and local-first, sitting beside Codex, Claude Code, or whatever runs your loop rather than replacing it: durable goals, executable todos, evidence logs, quota-aware auto-wake, and explicit gates where a human has to sign off. It is the least glamorous problem in agent tooling and the one that bites hardest — long-running work today dies at context boundaries and hands off as a wall of chat scrollback. Handoffs that carry verifiable state instead of narration is the right target; whether a separate kernel is the right shape, or whether the agents absorb this, is the open question.

### book-to-skill — turn a technical book into a skill your agent loads on demand
Point it at a PDF, EPUB, DOCX or Markdown pile and it produces a structured agent skill — frameworks, principles, techniques, anti-patterns — split into chapter files that only load when you ask about that topic. The measured claim is 24×–51× fewer tokens than dumping the book into context to answer one question. That framing matters more than the tool: the retrieval problem for reference material is mostly a chunking-and-routing problem, and skills turn out to be a workable index format. Works with Claude Code, Copilot CLI and Amp.
