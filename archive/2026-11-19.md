# Daily Dev Digest — 2026-11-19

> Theme: Agents get hands and hazards — your real browser, a poisoned repo, a verification playbook, and cheaper serving on Trainium

## Picks

### OpenCode Browse — an MCP server and Chromium extension that lends coding agents your real browser
Agents drive the browser you already use, with your tabs, logins and extensions, in background tab groups. It hands control back for logins, 2FA or payments and can restrict an agent to sites you list. It drew strong interest on Hacker News as agents need signed-in sites, not a blank headless profile. The page doesn't state a license, so check the repo.

### Poisoned repos that hijack coding agents — Bitdefender maps a credential-stealing campaign
Bitdefender Labs found 22 malicious GitHub links where planted AGENTS.md and CLAUDE.md files tell assistants such as Claude Code and Cursor to run a `setup.js` loader and hide its output. Repos can also ship `.claude/settings.json` session-start hooks that run once you trust the folder, with no AI cooperation needed. The loader goes after CI, cloud, registry and browser credentials, SSH keys and `.env` files, then writes itself into other agent config files. On the radar because agent instruction files are now an attack surface: read them before you trust a cloned repo.

### How the Claude Code team thinks about verification — a playbook for letting more agents run in parallel
Anthropic's write-up argues verification loops are what let you delegate more: keep a `verify` skill, favor E2E, property and differential tests, and keep a change from editing its own judge (review rules are read from the base branch). It also describes a commit gate with off/observe/enforce modes. Worth reading since the HN conversation this week is that review, not writing, is the bottleneck.

### TrnRT — an open-source LLM inference engine for AWS Trainium
Apache-2.0 engine serving an OpenAI-compatible API from a single trn2.48xlarge, with decode run as NKI megakernels. Currently supports only GLM-5.3-Flash. Interesting as a non-NVIDIA self-hosting path; the cost and throughput numbers are the project's own benchmark claims and we haven't reproduced them.
